# Module reference

The full per-module rows that `CLAUDE.md` summarises in one line each: coefficients, traps,
validation figures and headline numbers. Moved here verbatim on 2026-10-04 to keep `CLAUDE.md`,
which every session and subagent loads, small. Update the row here when a module changes, and
the one-liner in `CLAUDE.md` only if its trap changes.

| Module | What it already does |
|---|---|
| `frames.ReferenceFrames` | `rv_to_coe` and `coe_to_rv` — vectorised over `(N,3)`/`(N,6)`, handle circular/equatorial/polar/parabolic fallbacks, return a success mask. Also body-fixed, RaDec and long/lat transforms |
| `frames.ReferenceFrames` RSW | `RSW_basis(r, v)` → `(N,3,3)` with rows R, S, W; `cart_to_RSW(r, v, vec)` and `RSW_to_cart(r, v, vec_rsw)`. A `(3,)` direction such as prograde `[0,1,0]` broadcasts over N states. Success mask for rectilinear, zero or non-finite reference states — those rows come back exactly zero. The rectilinear test is *relative* (`|r×v| > tol·|r||v|`), unlike `rv_to_coe`'s absolute `|h|`, so the two masks can disagree near the boundary |
| `utilities.Transformations` | `Rx` `Ry` `Rz` `Rxyz` `Rzyx` `Rzxz` (batched `(N,3,3)` tensors), `cart_to_sphe` / `sphe_to_cart` |
| `utilities.Anomalies` | Full true ↔ eccentric ↔ mean stack including hyperbolic and parabolic, Newton-Raphson and successive-substitution solvers |
| `utilities.Kepler` / `utilities.Barker` | Time ↔ mean anomaly for elliptic/hyperbolic and parabolic cases |
| `simulator._topological_sort` | Vectorised BFS tier stratification — generic over any parent-index array |
| `database.py` | Polymorphic ORM: `BaseBodyORM` / `CelestialBodyORM` / `VesselORM` / `VirtualBodyORM` plus `SystemORM`. `VesselORM` already carries `dry_mass`, `fuel_mass`, `drag_area` |
| `kernels.py` | Compiled scalar kernels: `kepler_propagate`, `secular_j2_propagate`, `cowell_rk4_step`, `calc_global_states`, plus reusable `coe_to_rv_scalar` / `solve_kepler_scalar` / `advance_true_anomaly` |
| `scenarios.py` | `two_body`, `sun_earth_moon(moon_mu=…)`, `earth_constellation(n_sats=…)`, `powered_vessel(n_vessels=…, n_powered=…)`, `hohmann_pair()` (Earth plus four co-located massless vessels on one circular orbit — `KEPLER-SAT`/`COWELL-SAT` manoeuvre, `*-TWIN` are the controls; deliberately inclined and rotated so an RSW-vs-inertial frame error cannot hide) — shared by tests and benchmarks. `moon_mu=0.0` gives a massless Moon with a genuinely accelerating parent. `powered_vessel` returns Earth plus N co-located massless Cowell vessels, the first `n_powered` carrying `"thrust"` and the rest acting as **thrust-free twins** in the same arena (that is how a burn is separated from the gravity turn, and how integrator drift is measured). `eclipsed_satellite(n_sats=, altitude_km=, inclination_deg=)` seeds **Earth at the arena root** plus a massless luminous marker (`LIGHT_SOURCE_NAME`) 1 AU out on +x and satellites that pass through Earth's umbra once per orbit - it exists because a Cowell body in a *heliocentric* arena loses nine digits to cancellation and is round-off limited at **~1e-5 km** over 1.5 LEO orbits, so RK4's fourth order is **not observable** in `sun_earth_moon` at all, shadow or no shadow. `ground_station_pass(n_sats=, altitude_km=, inclination_deg=)` seeds Earth plus Keplerian vessels at true anomaly 180 deg for `geometry.py`'s closed-form pass, with companion constants `STATION_LATITUDE_DEG` / `STATION_LONGITUDE_DEG` / `STATION_ALTITUDE_KM` (the station is not a body — it lives in `geometry.py`'s arguments); its equatorial default is the only geometry with an exact answer, and its `inclination_deg` exists because that same symmetry hides a transposed SEZ axis. `zonal_twins(arg_pe_deg=(...), copies=2, semi_major_axis_km=, eccentricity=, inclination_deg=)` seeds `copies` co-located Cowell + pm + `j2` satellites per perigee (`zonal_twin_name(orbit, copy)`), copy 0 the J2 control - the differential idiom `zonal.py`'s orbit-dynamics tests need. `geostationary_satellites(longitudes_deg=, theta0=, omega=)` seeds Cowell + pm + `j2` satellites (`geo_satellite_name(k)`) **at rest in the rotating frame** at `geostationary_radius_km()` (42164.695 km, J2-synchronous) - rest is set by an `apply_delta_v` of `omega r - sqrt(mu/r)`, not by elements; tesseral left for the caller. **Build scenarios from here, never inline in a test** |
| `reference.py` | `reference_for(sim, times, oblateness={"Earth": (j2, r_eq)})` → DOP853 N-body truth trajectory, optionally with J2 on named bodies (reaction included, spin axis = frame +z). Independent of all engine code: oblateness is passed **explicitly**, never read from `force_model_params`, and the field is written from a different derivation than `geopotential.py`. Omitting it is bit-identical to the point-mass truth. `zonal={"Earth": (r_eq, {3: j3, 4: j4, 5: j5, 6: j6})}` adds J3..J6 the same way (explicit per-degree monomials, a different derivation from `zonal.py`'s recursion; degree 2 refused - J2 is `oblateness`'s) and is bit-identical when omitted; `run_sweep(zonal=)` forwards it. `tesseral={"Earth": (r_eq, omega, theta0, {(n, m): (C, S)})}` adds the m >= 1 field of degrees 2..4 rotating about +z (complex-phase monomials - no recursion, no rotation matrix; m = 0 refused; `theta0` at absolute sim time, shifted by `omega * sim.t`), bit-identical when omitted, forwarded by `run_sweep(tesseral=)` to both truths; with it `energy_drift` is the drift of the Jacobi integral `E - omega L_z`, since a rotating body does work. **For frontier-plot truth pass `rtol=TRUTH_RTOL, atol=TRUTH_ATOL` (1e-13, 1e-12)**: the default `atol=1e-9` governs LEO velocity components and costs ~4x in truth error (3.5e-9 against 8.6e-10 km per orbit). `energy_drift` is mu-weighted, so it certifies nothing about massless satellites |
| `api/` | **JSON layer** (2026-10-10). `catalog()`: scenario builders (exposed when they return a `Simulation` and every required parameter has a JSON form; JSON Schema with defaults per builder), force models (coefficients, body-valued coefficients from `catalog.BODY_PARAMS`, engine-owned columns from `ENGINE_OWNED`; fixtures and `ephemeris_third_body` hidden), propagators (KEPLERIAN / COWELL / SECULAR_J2), integrators. `describe_scenario(scenario)` builds and lists bodies (kind, mu, parent, default target, state). `validate_sweep(doc)` parses strictly (unknown keys are errors; all errors collected with JSON paths) and applies each config to a fresh build, so engine refusals come back against `configs[i]`; it also warns when truth lacks a field a config models (J2 without `truth.oblateness`; drag / SRP / thrust / tesseral, which truth omits). `run_sweep_request(doc)` -> `run_sweep`; `simulate(doc)` -> sampled global states. `config_to_json` / `config_from_json` round-trip `ModelConfig` (encounters, patches, regimes, station keeping refused, not dropped). `Limits(max_configs, max_steps, max_bodies, max_values)`. Bit-identical to the direct calls (`tests/unit/test_api.py`) |
| `benchmark.py` | `measure(fn)` → min-of-batches timing with noise ratio |
| `forces.py` | Force-model composition. `ForceKernel` is the contract a force model implements — additive (`+=`, never `=`), stateless, allocation-free, called once per model per evaluation. `AccelerationProvider` is what an integrator consumes: `(t, state) -> (C,3)`, with `state` explicit so RK sub-stages never touch the arena. Read the module docstring before writing a force model |
| `registry.py` | `@register_force_model(name, param_names=…, citation=…)` assigns the next uint64 mask bit. Optional `validate_bodies=` hook (`BodyValidator`), run by `enable_force_model` before any bit is set, for conditions a kernel cannot see. `get_force_model` / `all_force_models` / `mask_for`. Bits follow registration order within a process, so **sweep configs persist model names, never raw mask integers** |
| `geopotential.py` | Force model `"j2"` (`J2_MODEL`): the J2 perturbation only, relative to each body's `parent_indices` parent — not the central `-mu r/r^3` term. Coefficients `(j2, r_eq)` live on the *perturbed* body's row. Earth values `EARTH_J2` and `EARTH_R_EQ` = 6378.137 km (equatorial) — do **not** pair J2 with `scenarios.EARTH_RADIUS` (6371 km, mean), which is 0.2% off. Assumes the parent's spin axis is the frame's +z. Registered on `import orbital_engine`. The kernel cannot see a barycentre parent (it has no `is_system`), so `"j2"` registers `barycentre_parented` as its `validate_bodies` hook: `enable_force_model("j2", ...)` raises `ValueError` for such bodies before setting any bit. Writing `force_model_mask` directly bypasses it. Compiled twin: fused into `kernels.cowell_rk4_step` with RK4 and `point_mass_gravity` |
| `zonal.py` | Force model `"zonal"` (`ZONAL_MODEL`): the J3..J6 zonal perturbation of the `parent_indices` parent, **additive to `"j2"`, never a replacement** - a J2..J6 config enables both, `"j2"` keeps its fused twin and `SECULAR_J2` keeps reading `force_model_params["j2"]`. Coefficients `(r_eq, j3, j4, j5, j6)` (unnormalised `J_n`) on the perturbed body's row; spin axis = frame +z. Kernel: Legendre recursions, `a_n = (mu/r^2) J_n (R/r)^n [P'_{n+1}(s) r_hat - P'_n(s) z_hat]`; a zero `J_n` adds exactly nothing. EGM96 `EARTH_J3`..`EARTH_J6` (`EARTH_ZONALS` is the keyword set) from `EGM96_CBAR_N0` via `J_n = -sqrt(2n+1) Cbar_n0`, **from memory, unverified** - the same table's `Cbar_20` reproduces `EARTH_J2` within its printed digits (`EARTH_J2` is the truncation, 5.5e-14 low). Refuses barycentre parents, non-finite coefficients and `r_eq <= 0` on any row whose effective `J_n` is non-zero. **Fused into the compiled Cowell twin** (`kernels._cowell_accel`, per-body `has_zonal`, the same recursion in the same order): Cowell + pm + j2 + zonal stays compiled at **1.17x** the fused `j2` tier (0.0477 s against 0.0406 s at 15 s over 24 h; the NumPy fallback was ~120x), held to NumPy at 6.3e-13 relative over 1440 steps. A zonal body carrying a model outside the fused set (`srp`, `third_body`, `thrust`) still falls back; drag is fused too. Validated in `tests/validation/test_zonal.py`: against `reference.zonal_field` (<= 8.9e-14 of scale), a finite-differenced potential, bitwise parity, fourth-order convergence on zonal truth, and differentially against J2 twins - J3 `de/dt` +0.42 %, J4 `dRAAN/dt` +0.97 % against a 2 % budget. Headline (`benchmarks/zonal_sweep.py`, 12 sats, 550 km / 53 deg, 24 h, J2..J6 truth): omitting J3..J6 costs **1.26 km** median (RK4 at 15 s: 2.7e-3 km; at 60 s the 1.88 km truncation is larger) but only **0.07 s mean / 0.59 s max** rise shift, no pass lost - under the 1 s pad |
| `tesseral.py` | Force model `"tesseral"` (`TESSERAL_MODEL`): orders **m >= 1 of degrees 2..4** (nine C/S pairs) of the `parent_indices` parent, **additive to `"j2"` and `"zonal"`** (a 4x4 field enables all three). Coefficients `(r_eq, omega, theta0, c21, s21, ..., c44, s44)`, **unnormalised**; `EARTH_TESSERALS` / `EARTH_J22` from `EGM96_CS_BAR` via `unnormalise` (`N_nm = sqrt((2-delta_m0)(2n+1)(n-m)!/(n+m)!)`), **from memory, unverified** - normalisation checked against a remembered JGM-3 table to <= 1.5e-3. **The first kernel that reads `t`**: `theta = theta0 + omega * t`, **absolute sim time** (`geometry.py`'s convention at `epoch_s = 0`); body-fixed = `Rz(-theta)` of inertial. Kernel: Cunningham V/W recursion (Montenbruck & Gill 3.2.4-3.2.5, numbers unverified). Refuses barycentre parents, non-finite values, and `r_eq <= 0` **or `omega == 0`** on a row with any non-zero C/S (an unwritten omega silently freezes the field). Zero coefficients add exactly nothing. **Fused into the compiled Cowell twin** (`kernels._tesseral_term`, per-body `has_tesseral`, after zonal): `cowell_rk4_step` now takes the step's start `t` (`Simulation.t`, so a split sub-step starts at its own clock) and hands stages `t, t+dt/2, t+dt/2, t+dt` as `RK4Integrator` does; V/W scratch is arena-owned `_cowell_tesseral_vw`. Held to `tesseral_kernel` bit-identical field-level (bound 1e-12), state <= 1.9e-13 over 500 steps; the LEO tier **14.05 s -> 0.095 s** (1.56x fused J2..J6), every headline number unchanged. Validated in `tests/validation/test_tesseral.py`: truth field <= 1.5e-12 of scale, FD potential, co-rotating invariance, **fourth order (16.6) vs frozen stage time first order (1.995)** - the only tests that catch an RK4 stage-time bug - and GEO: J22 drift `+18 n^2 (R/a)^2 J22 sin 2(lambda - lambda22)` (plus sign, `lambda22 = atan2(S22,C22)/2` = -14.93 deg the long axis) within 8.2e-5 K of theory. Headline (`benchmarks/tesseral_sweep.py`): 4x4 stable slots **74.94 E / 105.09 W** (published 75.1 / 105.3, a comparison), east-west station keeping **1.764 m/s/yr** worst slot under J22, **2.066** under 4x4 (at 117.4 E); at LEO (550 km / 53 deg, 24 h) omitting tesserals costs **3.8 km median / 9.0 max** (3x J3..J6) and 0.29 s mean / **1.15 s max** rise shift, no pass lost |
| `drag.py` | Force model `"drag"`: `-(1/2) rho B |v_rel| v_rel`, with `v_rel = v - w x r` relative to `parent_indices` and the atmosphere co-rotating about the frame's +z (the same assumption as `j2`). Per-body coefficients are `(ballistic_coeff m^2/kg, rho0 kg/m^3, h0 km, scale_height km, r_ref km, omega rad/s, density_model, f107, f107a, ap, epoch_days)` - `f107`/`f107a`/`ap` read **only** on the two MSIS laws' rows and `epoch_days` (col 10) only on diurnal rows, so a legacy 7-column array still works, and the one unit conversion (`rho*B` from 1/m to 1/km, x1e3) sits in the kernel. `EARTH_OMEGA` is provided. `scale_height <= 0` means a silent zero contribution **under the single-band law only**. Refuses barycentre parents via `validate_bodies`; `validate_coefficients` refuses an unknown `density_model`, MSIS without **all three** indices in the same call (so `pymsis` never downloads them), the diurnal law without all three **and** `epoch_days`, solar indices on a non-MSIS row, `epoch_days` on a non-diurnal row, and out-of-range indices/epochs (1950-2050) - then evaluates the MSIS profile or diurnal table, before any bit is set. **Fused into the compiled Cowell twin** (`kernels._cowell_accel`, per-body `has_drag`, density laws 0-2 - a **diurnal (3.0) row is foreign** to `_refresh_cowell_plan` and sends the Cowell set to NumPy, since the twin has no `t` and would decode 3.0 as MSIS; a row switched to 3.0 by *direct assignment* after planning is read as averaged MSIS until the next re-plan, the same arithmetic in the same order, each RK4 stage fed its own stage velocity `pv + v_k` exactly as `RK4Integrator` writes it): the layered table and each MSIS triple's memoised profile are stacked at plan time by `drag.density_tables` (row 0 the table, one row per distinct triple, `_cowell_drag_table_of` per body) and searched by a scalar binary search reproducing `np.searchsorted(side="right")` and its clipped terminal bands; the selector and every coefficient are read live, and an MSIS row whose live indices no longer match its planned profile makes the kernel return that slot having written nothing, so `step()` re-plans (an unevaluated triple then falls back, and the reference raises `LookupError` as before). Held to `drag_kernel` at **1.7e-14** of `|a_drag|` field-level (bound 1e-12; band edges exactly and an ulp either side, both extrapolated regions, heliocentric parent) and the state to 1.6e-13 by norm over 500 steps. Cost: drag adds ~0.16 us per body-step on top of the fused `j2` tier's 0.076 (all three laws within 5 % of each other: `exp` dominates, the band search does not); the station-keeping figure's 10-day run went **41.3 s -> 9.7 s** and `benchmarks/msis_sweep.py` **317 s -> 19 s**, every printed number unchanged. The Cowell step composes `_gravity_accel`, `_drag_term`, `_zonal_term` itself behind their flags - passing the tables through one per-stage call tripled the pm/j2 tiers' cost. Validated against orbit-averaged decay, energy balance and the co-rotation factor (`tests/validation/test_drag.py`) |
| `atmosphere.py` | The density law `"drag"` uses, selected per body by its `density_model` coefficient - **not** a second force model and **not** a mask bit, so it is one more key in a `sweep.ForceModelSpec`'s `coefficients`. `DENSITY_MODEL_EXPONENTIAL` = 0.0 is the single band and is what an **unwritten (all-zero) row already selects**, so every pre-existing configuration is unchanged; `DENSITY_MODEL_LAYERED` = 1.0 is Vallado 4e Table 8-4, 28 piecewise-exponential bands from 0 to 1000+ km, evaluated by one vectorised `np.searchsorted`. Under the layered law `rho0`, `h0` and `scale_height` are **ignored**. The table is **transcribed from memory and unverified against the text**; its internal check is continuity, which 27 of 28 boundaries pass inside 1e-4 - the 0-25 km boundary closes to 1.4e-3 against a 7.7e-4 rounding bound and is asserted as a **named anomaly**, so treat `H = 7.249 km` as the table's least trustworthy entry. Extrapolates the terminal bands at both ends; a masked row returns exactly 0.0 without evaluating `exp`. Compiled twin: in `drag`'s fused Cowell term (see its row), all three laws. The headline comparison: over 3 days from 355 km at `B = 0.4 m^2/kg` the table predicts **27.1 km more decay** than a single band matched at 355 km with `H = 60 km`, 30 % more, each within 1.9e-4 of its own orbit-averaged mean ODE (`tests/validation/test_atmosphere.py`). **`DENSITY_MODEL_MSIS` = 2.0 is NRLMSIS 2.0 via `msis_bridge.py`** (`[msis]` extra, `pymsis` imported lazily, `version=2.0` pinned): `pymsis` is **never called in a step** - `drag`'s `validate_coefficients` evaluates, once per `(f107, f107a, ap)`, the global mean over latitude (8 Gauss-Legendre), local time (8) and day of year (24) at 601 nodes 0-1000 km (1.3 s), **memoised as a pure function of the triple**; the kernel evaluates it log-linearly through the shared `piecewise_exponential_density` (+29 us/call) and **raises `LookupError`** on an unevaluated triple rather than evaluating lazily. Presets `SOLAR_ACTIVITY_LOW/_MODERATE/_HIGH` (ECSS 65/65/0, 140/140/15, 250/250/45, from memory), `msis_coefficients(...)` for a `ForceModelSpec`. **The average discards** the diurnal bulge (2.30x at 400 km), the season (1.63x) and index time variation - a model choice. Legacy rows **bit-identical** (frozen pre-MSIS kernel; 2000-step run). Table vs moderate MSIS, 150-1000 km: **0.79 (800 km) to 1.28 (160 km)**, a plausibility check, not verification. **Headline** (`benchmarks/msis_sweep.py`, 6 days, station-keeping scenario, baseline MSIS moderate 3.047 m/s/day): solar low **-71.9 %**, high **+134.4 %**, table +12.8 %, single band -3.1 %, each within 6e-4 of its pre-run prediction - **solar activity is 5-10x the atmosphere-model choice**, and the static laws straddle moderate MSIS. Validated in `tests/validation/test_msis.py` / `_wiring.py` / `_delta_v.py`. **`DENSITY_MODEL_MSIS_DIURNAL` = 3.0 is NRLMSIS 2.0 with the diurnal bulge via `msis_diurnal.py`**: at configuration time, per `(f107, f107a, ap, UT day of epoch_days)`, the **zonal mean at fixed mean local solar time** (6 UT samples, `lon = 15(s - UT)`; one UT would pin a 1.3 % rms / 4 % max longitude structure) on 601 alt x 37 lat (5 deg) x 48 LST (30 min, periodic) nodes, **9.4 s**, memoised, `LookupError` on a miss; step-time trilinear in `ln rho`. **The only density law that reads `t`**: `LST = 12 h + (alpha_sat - L(t))/15`, `L` the Sun's **mean** longitude (`solar_ephemeris.py`, Astronomical Almanac low-precision Sun, from memory, validated to 0.004 deg at the 2024 equinoxes/solstices) - mean, not apparent, because MSIS's own local time is `UT + lon/15` (matched to 0.15 s via IAU 1982 GMST; apparent is off by the equation of time, up to 16 min); latitude = geocentric declination (<= 0.2 % vs geodetic). **Season frozen at the epoch's day** (+1.4 % drift in 10 days at 400 km from the March equinox). Table nodes = direct MSIS to 3.6e-15; off-node error = its leading term to 6 %; over lat/LST/24 days it reproduces the averaged law's quadrature to 2.8e-6 (its profile to 0.14 %, the profile's 00:00 UT bias). **Headline** (`benchmarks/msis_diurnal_sweep.py`, `msis_sweep.py`'s band, dawn-dusk vs noon-midnight SSO with J2): the diurnal law's budget error = season x local-time factor, each predicted from the table before running and measured within 6.3e-3 on `(1+e)`: 2024-03-20 dawn-dusk **+7.3 %**, noon-midnight **+14.6 %**; 2024-07-01 **-21.9 %** / **-16.0 %** (baseline 3.341 m/s/day). Over 2024 the local-time factor alone is **0.935-0.965** dawn-dusk, **1.004-1.050** noon-midnight; the season **0.80-1.13** - so the average over-budgets a dawn-dusk SSO by 4-7 % through local time (half the ~14 % atmosphere-model choice, a twentieth of solar activity's -72/+134 %) and mis-budgets any SSO by up to 20 % through the season. Build with `scenarios.sun_synchronous_satellites(epoch_days=, ltan_hours=(18, 12), altitude_km=)` (Cowell + pm + J2, `sun_synchronous_inclination_deg`; the plane precesses **+0.52 %** faster than the Sun because the mean `a` sits 9.8 km below an osculating seed - not the 5.0 km of the mean *altitude*). Validated in `tests/validation/test_msis_diurnal.py` / `_wiring.py` / `test_solar_ephemeris.py` |
| `srp.py` | Force model `"srp"` (`SRP_MODEL`): cannonball solar radiation pressure, `a = -nu * cr * p_srp * (A/m) * (AU/d)^2 * u_hat` with `u_hat` pointing body->source, so the push is **anti-sunward**. The light source is a float slot in column `source` and is **mandatory**, named in sweeps as `ForceModelSpec(..., body_coefficients={"source": "Sun"})` exactly like `third_body`'s perturber; `p_srp` is mandatory too (`SOLAR_PRESSURE_1AU` = 4.5598e-6 N/m^2 = 1367/c; the IAU 2015 TSI 1361 gives 0.44 % less). Coefficients `(cr, area_mass m^2/kg, p_srp N/m^2, source, r_occ km, r_source km, shadow_model)`; the one unit conversion is `1e-3`. **The occulter is the Keplerian parent**; `r_occ <= 0` disables the shadow (the heliocentric case). `shadow_model` selects the geometry the way `drag`'s `density_model` selects a density law: `SHADOW_MODEL_CYLINDRICAL` = 0.0 (the all-zero default, `nu` exactly 0 or 1) or `SHADOW_MODEL_CONICAL` = 1.0 (apparent-disc overlap, umbra/penumbra/annular, continuous). **The cylinder's terminator is a genuine discontinuity and costs RK4 its order** - measured step-halving ratio 1.96 where a smooth problem gives 16, and 7x the error of no shadow at all; conical is indistinguishable from no shadow, which is the reason to prefer it. Exports `umbra_clearance` (the cylindrical terminator as a *signed scalar*, negative inside the umbra), `shadow_clearance` (the `(sim, bodies)` event adapter), `cylindrical_shadow_bodies` and `latch_shadow_branch`; column 7 `shadow_latch` is **engine-owned state** written and released inside one step by `events.py` and refused as a user coefficient. The cylinder's order loss is now **fixable**: `sim.add_event(events.shadow_event(sim))`. `validate_coefficients` rejects a missing/non-slot/self/parent/barycentre/inactive source, `cr` outside [0,2], negative areas or radii, an unknown `shadow_model`, a conical shadow with no `r_source`, and a barycentre-parented body asking for a shadow. The frozen-source lag is negligible here (5e-6 km/day at dt=60 s). Foreign to the fused plan, so Cowell runs on NumPy. No compiled twin. **SRP overtakes drag at 631 km** under `atmosphere.py`'s table at `C_r/C_d = 1.3/2.2` (A/m cancels exactly); the usual 800 km figure assumes ~8x that density. Validated in `tests/validation/test_srp.py` against the closed form, an independent disc-overlap quadrature, and the orbit-averaged Gauss rate `<de/dt> = -(3/2)(h_hat x f)/(n a)` (predicted 2.674e-5, measured 2.678e-5, 0.76 %) |
| `gravity.py` | Force model `"point_mass_gravity"`: the central term `-(mu_body + mu_parent) r / r^3` relative to `parent_indices`, the same summed mu the Keplerian path uses. Parent only, so a two-body term and **not** N-body or third-body. Registered on `import orbital_engine`. Name constant `POINT_MASS_MODEL`. Compiled twin: fused into `kernels.cowell_rk4_step` |
| `thirdbody.py` | Force model `"third_body"` (`THIRD_BODY_MODEL`): one named perturber's point-mass pull relative to `parent_indices`, **direct minus indirect** `mu_s[(r_s-r)/\|r_s-r\|^3 - r_s/\|r_s\|^3]`. The perturber is a float slot in `force_model_params["third_body"]` column `perturber`, and it is **mandatory**. In sweeps give it by name: `ForceModelSpec(..., body_coefficients={"perturber": "Sun"})`, resolved by `apply_config`. It is validated through the registry's `validate_coefficients` hook, which rejects self, parent, barycentre, inactive and massless perturbers.
